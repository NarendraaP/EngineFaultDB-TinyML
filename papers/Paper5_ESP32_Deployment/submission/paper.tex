\begin{abstract}
Deploying deep learning on resource-constrained 32-bit microcontrollers (TinyML) requires empirical hardware characterization to bridge the substantial translation gap between host simulation and physical silicon. However, ultra-low-resource tabular diagnostic models ($<4$\,KB Flash, sub-$100\,\si{\micro\second}$ execution latency) remain significantly under-characterized on commercial microcontrollers compared to vision and audio workloads. This paper presents a comprehensive on-device empirical characterization of four disk-verified \texttt{FULL\_INT8} Multi-Layer Perceptron (MLP) models deployed on an Espressif ESP32-D0WD-V3 microcontroller (dual-core Xtensa LX6 @ $240\,\text{MHz}$, $4\,\text{MB}$ Flash, $320\,\text{KB}$ SRAM). Using a high-precision zero-I/O in-RAM hardware timer benchmarking protocol across $24,000$ measured single-sample inferences, we establish four primary findings: (1) isolated on-device latency scales strictly monotonically with parameter count ($R^2 = 0.963$) from $64.55\,\si{\micro\second}$ ($176$ parameters) to $89.90\,\si{\micro\second}$ ($412$ parameters); (2) structural knowledge distillation delivers an observed $28.20\%$ physical execution latency reduction relative to the uncompressed baseline; (3) host x86\_64 profiling underestimates physical microcontroller execution latency by $62.87\times\text{--}76.77\times$ and introduces sub-microsecond rank inversions unmasked on silicon; and (4) TensorFlow Lite for Microcontrollers commits exactly $916\,\text{Bytes}$ of static tensor arena memory with zero dynamic heap allocations across $25,200$ consecutive executions. These empirical results provide rigorous, reproducible baselines for deploying real-time intelligence on edge cyber-physical and industrial diagnostic systems.
\end{abstract}

\section{Introduction}
\IEEEPARstart{T}{he} integration of Tiny Machine Learning (TinyML) to run trained models on low-power, resource-constrained 32-bit microcontrollers (MCUs) is emerging as a new paradigm in edge computing~\cite{warden2019tinyml,ray2022review,saha2022tinyml}. By executing inference on bare-metal silicon at the sensor edge, these edge devices provide extreme latency, zero telemetry bandwidth, reduced radio power, and privacy~\cite{banbury2021benchmarking,schizas2022tinyml}. For edge applications where the inference decisions are critical for safety or business operations such as high-frequency industrial vibration monitoring, engine diagnostics, acoustic anomaly detection, and embedded cyber-physical control, the edge devices must make inferences with tight latency budgets ($\le 5\text{--}100\,\text{ms}$) and sub-milliwatt power consumption~\cite{nguyen2024quantized,puranik2024benchmarking}.

Despite rapid algorithmic advances in neural network compression and pruning, a fundamental hardware translation gap persists between host-side software simulations and physical microcontroller execution~\cite{david2021tensorflow,imteaj2023benchmarking}. Host x86\_64 development workstations employ deep out-of-order execution pipelines, multi-level branch predictors, multi-megabyte cache hierarchies, and advanced vector SIMD units (AVX2/AVX-512). These outboard microarchitectural features mask instruction-level bottlenecks, memory stall penalties, and register pressure that dominate embedded execution on deeply constrained 32-bit RISC microcontrollers~\cite{banbury2021benchmarking,lin2020mcunet}. As a result, models that appear optimal during host-side training often demonstrate poor execution latency, memory overhead, or runtime non-determinism when flashed to physical MCU hardware~\cite{blalock2020state}.

Furthermore, the existing TinyML benchmarking literature suffers from two notable limitations:
\begin{enumerate}
    \item \textbf{Workload Bias Toward Vision and Audio:} Standard benchmark suites such as MLPerf Tiny focus on 2D Convolutional Neural Networks (CNNs) for visual wake words, image classification, and keyword spotting~\cite{banbury2021benchmarking,lin2021mcunetv2}. These CNNs typically have $> 100$\,KB footprint in Flash ROM with inference latencies ranging from $10\,\text{ms}$ to $300\,\text{ms}$. In comparison, ultra-low resource tabular diagnostic networks ($< 4$\,KB Flash, $< 100\,\si{\micro\second}$ execution latency) are largely uncharacterized on commercial silicon.
    \item \textbf{Methodological Timing Artifacts:} Prior embedded benchmarking studies often log timestamps or intermediate results over serial UART buses as part of the measurement loop~\cite{saha2022tinyml,schizas2022tinyml}. UART transmission at typical baud rates ($115,200\,\text{bps}$) introduces multi-millisecond driver blocking delays that overshadow true kernel execution time by orders of magnitude.
\end{enumerate}

To address these challenges, this paper presents an empirical, publication-grade on-device characterization and latency profiling of four verified, disk-serialized \texttt{FULL\_INT8} Multi-Layer Perceptron (MLP) models deployed on physical Espressif ESP32-D0WD-V3 microcontroller silicon (dual-core Xtensa LX6 @ $240\,\text{MHz}$, $4\,\text{MB}$ Flash, $320\,\text{KB}$ SRAM). Figure~\ref{fig:physical_pipeline} illustrates our physical deployment and zero-I/O measurement pipeline.

We structure our investigation around five concrete Research Questions (RQs):
\begin{itemize}
    \item \textbf{RQ1 (On-Device Latency Distributions):} How do ultra-compact \texttt{FULL\_INT8} MLP architectures differ in empirical single-sample inference latency distributions on bare-metal ESP32 silicon?
    \item \textbf{RQ2 (Compute-to-Latency Translation):} How do parameter counts and theoretical Multiply-Accumulate (MAC) operations translate to physical execution latency, and what speedup does structural knowledge distillation deliver on silicon?
    \item \textbf{RQ3 (Host-to-Silicon Translation Gap):} How does host-measured x86\_64 execution latency differ quantitatively from physical microcontroller execution, and does host profiling introduce microarchitectural rank inversions?
    \item \textbf{RQ4 (Memory Subsystems \& Determinism):} What exact Flash ROM, internal static SRAM, dynamic tensor arena, and heap characteristics are observed during physical execution?
    \item \textbf{RQ5 (Real-Time Cyber-Physical Feasibility):} How do measured on-device execution latencies map onto real-time cyber-physical deadlines, and what single-sample compute equivalents are achievable per core?
\end{itemize}

\subsection{Key Contributions}
The main contributions of this paper are summarized as follows:
\begin{enumerate}
    \item \textbf{High-Density Empirical Silicon Dataset:} We execute and capture $24,000$ individual single-sample on-device inferences across four verified \texttt{FULL\_INT8} MLP models ($N=6,000$ measurements per model across 3 independent rounds), establishing complete parametric and percentile latency distributions (Mean, Median, Std.~Dev., P95, P99, Min, Max, IQR, CV).
    \item \textbf{Zero-I/O In-RAM Timing Protocol:} We formulate and implement a decoupled measurement methodology that records execution timestamps directly into pre-allocated static RAM using the $240\,\text{MHz}$ hardware APB timer (\path{esp_timer_get_time()}), completely eliminating UART driver blocking delays.
    \item \textbf{Quantification of Host-to-Silicon Divergence:} We demonstrate that host x86\_64 profiling underestimates physical microcontroller execution latency by $62.87\times$ to $76.77\times$, unmasking a sub-microsecond rank inversion where host-side superscalar caching obscures true integer ALU instruction scaling.
    \item \textbf{Rigorous Memory Subsystem Accounting:} We provide exact physical memory allocations across Flash partitions, internal static SRAM, TensorFlow Lite Micro tensor arena buffer allocation ($916\,\text{Bytes}$ committed out of $8,192\,\text{Bytes}$), and demonstrate zero heap allocation and zero memory leakage across $25,200$ invocations.
    \item \textbf{Fully Open-Source Reproducibility:} All firmware code, PlatformIO configuration files, compiled TFLite FlatBuffers, C-byte array headers, Python parsing pipelines, and raw serial logs are openly shared to enable full community replication and verification.
\end{enumerate}

\section{Silicon Platform and Deployment Architecture}

\subsection{Physical Silicon Platform}
All physical hardware experiments were performed on an Espressif ESP32-D0WD-V3 microcontroller (silicon revision v3.1). Table~\ref{tab:hardware_config} summarizes the audited hardware and software environment. The ESP32-D0WD-V3 microcontroller incorporates two independent 32-bit Xtensa LX6 microprocessor cores running at a fixed $240\,\text{MHz}$ clock frequency ($4.167\,\text{ns}$ clock period) with a $40\,\text{MHz}$ external crystal oscillator. 

The processor architecture features a 7-stage scalar pipeline, a 32-bit general-purpose register file, single-cycle integer arithmetic and logic units (ALU), and dedicated hardware integer multiply-accumulate units. The physical board integrates $4\,\text{MB}$ of external Quad-SPI Flash memory operating at $80\,\text{MHz}$ in Quad-I/O (QIO) mode and $320\,\text{KB}$ of internal on-chip static RAM (SRAM). External Pseudo-Static RAM (PSRAM) was deliberately not present on the module, ensuring that all program stacks, static model buffers, and dynamic tensor arenas executed strictly within high-speed, zero-wait-state internal SRAM.

\subsection{Quantized Integer Execution Semantics and Kernel Stack}
The firmware was compiled using PlatformIO with the GCC compiler utilizing the \texttt{-O3} optimization flag. To ensure architecture-independent reproducibility and prevent proprietary assembly lock-in, our firmware integrates the official TensorFlow Lite for Microcontrollers (TFLM) runtime utilizing a portable reference C++ implementation of quantized integer matrix multiplication (\texttt{tflite::reference\_integer\_ops::FullyConnected}) registered within a custom \texttt{ref\_fc} resolver namespace.

For an 8-bit quantized fully-connected layer computing output activations $q_3 \in [-128, 127]$ from input activations $q_1$ and weights $q_2$, the mathematical transformation is formalized as:
\begin{equation}
    q_3 = \text{clip}\left( \left\lfloor M \sum_{k} (q_{1,k} - z_1)(q_{2,k} - z_2) + b \right\rceil + z_3, -128, 127 \right)
\end{equation}
where $z_1, z_2, z_3 \in \mathbb{Z}$ represent the asymmetric integer zero-points of the input, weight, and output tensors, respectively; $b \in \mathbb{Z}$ represents the 32-bit quantized bias; and $M \in (0, 1)$ is the real-valued scale multiplier decomposed into fixed-point integer arithmetic:
\begin{equation}
    M = 2^{-n} M_0, \quad M_0 \in [2^{30}, 2^{31}-1], \quad n \in \mathbb{Z}^+
\end{equation}
During runtime execution on the Xtensa LX6 core, the reference kernel computes inner products using 32-bit integer accumulation registers, followed by a fixed-point multiplication with $M_0$ and an arithmetic right-shift by $n$ bits. This reference execution stack establishes an unadulterated baseline for standard Xtensa scalar integer ALU execution without SIMD acceleration.

\subsection{Zero-I/O In-RAM Timing Protocol}
A pervasive source of error in embedded machine learning benchmarking is serial logging interference~\cite{banbury2021benchmarking,saha2022tinyml}. When serial print statements are placed inside or adjacent to the measurement loop, UART transmission overhead (typically $>86\,\si{\micro\second}$ per transmitted byte at $115,200\,\text{bps}$) introduces multi-millisecond driver blocking and interrupt handling delays that completely corrupt microsecond-scale kernel measurements.

To eliminate I/O interference, our protocol implements a decoupled zero-I/O measurement pipeline:
\begin{enumerate}
    \item \textbf{Isolated Kernel Scope:} Timing strictly isolates the model execution invocation:
    \begin{equation}
        t_{\text{start}} = \text{\path{esp_timer_get_time}}(), \quad \text{Invoke}(), \quad t_{\text{end}} = \text{\path{esp_timer_get_time}}()
    \end{equation}
    where pure execution latency is captured as $\Delta t = t_{\text{end}} - t_{\text{start}}$. All sensor normalization, data copying, and post-processing are strictly excluded.
    \item \textbf{In-RAM Accumulation:} Every individual measurement $\Delta t$ is stored directly into a pre-allocated static RAM array (\texttt{uint32\_t latencies[2000]}) without invoking memory allocation or serial output.
    \item \textbf{Post-Hoc Statistical Sorting:} After all $2,000$ iterations of a benchmark round complete, the microcontroller sorts the latency array on-chip using \texttt{std::sort} ($\mathcal{O}(N \log N)$) to extract exact parametric and percentile metrics before serializing summary records over UART.
\end{enumerate}

\subsection{Multi-Round Statistical Protocol}
To evaluate execution stability across physical thermal conditions and eliminate transient startup anomalies, the experimental protocol enforces:
\begin{enumerate}
    \item \textbf{Pipeline Warmup:} Exactly $100$ un-timed single-sample inferences precede every measurement round to warm instruction caches and pipeline branch buffers.
    \item \textbf{Replication Density:} Exactly $3$ independent benchmark rounds per model, with $2,000$ timed single-sample inferences per round. Across the 4 models, this constitutes $N=6,000$ measured inferences per model and $N=24,000$ measured inferences across the portfolio (plus $1,200$ warmup inferences; $25,200$ total physical invocations).
    \item \textbf{Hardware Timer Resolution:} The ESP32 high-resolution timer (\path{esp_timer_get_time()}) provides $1\,\si{\micro\second}$ resolution derived from the $240\,\text{MHz}$ APB clock, providing high temporal accuracy without software timer jitter.
\end{enumerate}

\section{Empirical Silicon Latency Characterization}

Table~\ref{tab:latency_stats} and Figure~\ref{fig:latency_and_params}(a): Complete empirical (hardware silicon) latency metrics are shown here. It is observed that in all cases, multiple measurements taken in lab benchmark setting are consistent with each other, with $<0.03\,\si{\micro\second}$ of standard variation between the three independently obtained rounds.

\subsection{RQ1: Silicon Latency Distributions and Monotonic Scaling}
As can be seen in Table~\ref{tab:latency_stats}, the mean single sample inference latencies range from $64.55\,\si{\micro\second}$ for \texttt{student\_a\_8\_4\_int8} to $89.90\,\si{\micro\second}$ for \texttt{mlp\_14f\_int8}. The latency distributions show very little inter-quartile range ($\text{IQR} = \text{P75} - \text{P25}$) for all four models (exactly $2.0\,\si{\micro\second}$) and coefficients of variation ($\text{CV} = \sigma/\mu$) between $2.96\%$ and $6.8\%$. Tail latencies are very consistent as well, with 99th percentile ($\text{P99}$) within $11.1\text{--}13.8\,\si{\micro\second}$ of the medians.

The physical measurements demonstrate a strictly monotonic trend within the evaluated model set:
\begin{equation}
    t_{\text{student\_a}} < t_{\text{student\_b}} < t_{\text{mlp\_12f}} < t_{\text{mlp\_14f}}
\end{equation}
This monotonicity proves that on 32-bit RISC bare-metal microcontrollers without out-of-order execution, the execution latency is strictly dictated by the sequential multiplication and accumulation of quantized integer weights across 32-bit processor registers.

\subsection{RQ2: Parameter Scaling and Distillation Speedup}
Figure~\ref{fig:latency_and_params}(b) plots model parameter count against measured on-device execution latency. Linear regression reveals a strong linear relationship:
\begin{equation}
    \text{Latency} (\si{\micro\second}) \approx 0.106 \times \text{Parameters} + 42.10 \quad (R^2 = 0.963)
\end{equation}
Similarly, theoretical active Multiply-Accumulate (MAC) counts have strong linear correlation ($R^2 = 0.954$). The non-zero intercept ($42.10\,\si{\micro\second}$) captures TFLM framework invocation overhead for tensor pointer resolution, activation quantization scaling, and layer invocation dispatch.

Comparing the compact distilled model \texttt{student\_a\_8\_4\_int8} against the uncompressed \texttt{mlp\_14f\_int8} baseline demonstrates an observed on-device latency reduction of:
\begin{equation}
    \Delta L = \frac{89.90\,\si{\micro\second} - 64.55\,\si{\micro\second}}{89.90\,\si{\micro\second}} \times 100\% = \mathbf{28.20\%}
\end{equation}
This confirms that structural knowledge distillation physically reduces on-chip execution cycles on embedded ALUs by eliminating intermediate tensor channels and matrix inner products.

\subsection{RQ5: Real-Time Cyber-Physical Feasibility}
Across all $25,200$ physical executions, the \textbf{empirical maximum observed latency} was $102\,\si{\micro\second}$ (observed on \texttt{mlp\_14f\_int8}). When evaluated against standard embedded cyber-physical control deadlines ($5\,\text{ms}$ to $100\,\text{ms}$), execution consumes at most $2.04\%$ of the tightest $5\,\text{ms}$ deadline, providing an observed feasibility headroom of $\mathbf{97.96\%}$ at $D=5\,\text{ms}$ and $\mathbf{99.90\%}$ at $D=100\,\text{ms}$. We explicitly emphasize that this reflects empirical feasibility under tested conditions and does not establish a formal static Worst-Case Execution Time (WCET) bound.

Converting mean latencies to reciprocal throughput capacity, \texttt{student\_a\_8\_4\_int8} provides single sample compute equivalent of $15,491.9\,\text{inferences/sec}$ per single $240\,\text{MHz}$ core (pure compute-bound, batch=1). System throughput will be naturally limited by physical sensor Analog-to-Digital Converter (ADC) acquisition times, Direct Memory Access (DMA) transfer rates, and Controller Area Network (CAN) bus scheduling periods.

\subsection{RQ3: Quantitative Slowdown and Rank Inversions}
Table~\ref{tab:host_vs_esp32} and Figure~\ref{fig:host_vs_esp32} compare physical ESP32 latency against host x86\_64 measurements for identical serialized TFLite FlatBuffers. 

This comparison reveals two critical insights:
\begin{enumerate}
    \item \textbf{Substantial Translation Slowdown:} Physical microcontroller execution is $62.87\times$ to $76.77\times$ slower than host x86\_64 execution. Host-side timing fails completely as an absolute predictor of embedded execution.
    \item \textbf{Sub-Microsecond Rank Inversion:} On host x86\_64, \texttt{student\_b\_16\_4\_int8} exhibited the lowest latency ($0.98\,\si{\micro\second}$), while \texttt{student\_a\_8\_4\_int8} ranked third ($1.02\,\si{\micro\second}$). On physical silicon, this ranking is cleanly inverted: \texttt{student\_a} is strictly fastest ($64.55\,\si{\micro\second}$, Rank 1), followed by \texttt{student\_b} ($72.96\,\si{\micro\second}$, Rank 2).
\end{enumerate}

\subsection{Microarchitectural Explanation of Divergence}
The cause of this rank inversion lies in microarchitectural divergence:
\begin{itemize}
    \item \textbf{Host x86\_64 Execution:} The host CPU (AMD Ryzen / Intel Core) features wide superscalar pipelines, speculative execution, aggressive branch prediction, and multi-megabyte L1/L2/L3 cache hierarchies. For ultra-small models ($<4$\,KB), the entire model and tensor graph reside permanently in the L1 instruction and data caches. Sub-microsecond execution time is dominated by operating system thread scheduling jitter and timer interrupt noise rather than integer ALU compute cycles.
    \item \textbf{Bare-Metal MCU Silicon:} On the 32-bit Xtensa LX6 core, instruction execution is in-order and scalar. With zero cache prefetching and fixed clock frequencies ($240\,\text{MHz}$), the physical latency is strictly proportional to the number of scalar integer instruction cycles required to execute matrix inner products. Physical benchmarking reveals the true algorithm scaling that is obscured by host noise floors.
\end{itemize}

\subsection{RQ4: Memory Partitioning and Tensor Arena Accounting}
Table~\ref{tab:memory_breakdown} details the physical memory breakdown on the ESP32 platform:
\begin{itemize}
    \item \textbf{Flash ROM Footprint:} The complete compiled firmware image takes $330,153\,\text{Bytes}$ ($25.19\%$ of standard $1.25\,\text{MB}$ application partition, $7.87\%$ of physical $4\,\text{MB}$ SPI Flash). All four models together need $< 15\,\text{KB}$ of static ROM embedding.

When initializing the model, the TFLM runtime allocator committed exactly $\mathbf{916\,\text{Bytes}}$ to host input tensors, layer activations, scratch buffers and output tensors, leaving an unallocated arena headroom of $\mathbf{88.82\%}$.
\end{itemize}

\subsection{Dynamic Heap Stability and Zero-Leakage Verification}
A critical requirement for industrial edge deployments is memory determinism. Dynamic memory allocation through \texttt{malloc} or \texttt{new} inside an inference loop leads to heap fragmentation, non-deterministic allocation latency, and possible out-of-memory crashes.

Our runtime monitoring verified:
\begin{enumerate}
    \item \textbf{Zero Runtime Allocations:} Across all $25,200$ consecutive invocations of the algorithm, zero runtime dynamic memory allocations were requested from the system heap.
    \item \textbf{Constant Free Heap:} Free heap memory was constant at $237,452\,\text{Bytes}$ before, during and after benchmark execution, verifying $0\,\text{Bytes}$ of memory leakage.
\end{enumerate}

\section{Cyber-Physical Edge Deployment Considerations}

\subsection{Dual-Core FreeRTOS Task Partitioning}
The ESP32-D0WD-V3 features two independent Xtensa LX6 cores (Core 0 and Core 1). Industrial cyber-physical systems require simultaneous sensor sampling at high-frequency (e.g., $10\,\text{kHz}$ vibration ADC sampling) and communication intensive workloads (e.g., $1\,\text{Mbps}$ CAN bus message processing) alongside machine learning inference.

Our empirical characterization indicates a recommended architectural partitioning:
\begin{itemize}
    \item \textbf{Core 0 (I/O and Communications):} Handles FreeRTOS interrupt handling, ADC Direct Memory Access (DMA), and network communications (CAN / BLE / Wi-Fi).
    \item \textbf{Core 1 (Dedicated TinyML Inference):} Dedicated to pure in-RAM neural network execution. Since independent inference needs $< 90\,\si{\micro\second}$, Core 1 can run periodic inference windows without disrupting real-time sensor sampling pipelines on Core 0.
\end{itemize}

\subsection{ISA Portability and Hardware Accelerators}
While our benchmarks evaluate the portable reference C++ integer kernel on standard Xtensa LX6 ALUs, alternative microarchitectures offer dedicated hardware acceleration:
\begin{itemize}
    \item \textbf{ARM Cortex-M (CMSIS-NN):} ARM Cortex-M4/M7/M55 microcontrollers have SIMD instructions (\texttt{SMLAD}) which perform two 16-bit multiplications and 32-bit accumulation per one clock cycle.
    \item \textbf{ESP32-S3 (ESP-NN):} Newer ESP32-S3 SOC has Xtensa LX7 cores with custom vector instructions, which provide $2\times\text{--}4\times$ accelerations for large convolution layers~\cite{puranik2024benchmarking}.
\end{itemize}
Our reference measurements provide a technology-neutral baseline characterizing unadulterated scalar integer execution.

\section{Related Work}
Benchmarking embedded machine learning has advanced rapidly. Banbury et al.~\cite{banbury2021benchmarking} established MLPerf Tiny to standardize cross-platform evaluation across vision, audio, and anomaly detection. David et al.~\cite{david2021tensorflow} introduced the architecture and arena management principles of TensorFlow Lite for Microcontrollers. Lin et al.~\cite{lin2020mcunet,lin2021mcunetv2} developed MCUNet, co-designing neural architectures and memory-efficient runtime engines for Cortex-M microcontrollers. Liberis et al.~\cite{liberis2021munas} explored constrained neural architecture search ($\mu$NAS) for microcontrollers.

Integer quantization foundations were formalized by Jacob et al.~\cite{jacob2018quantization} and Warden and Situnayake~\cite{warden2019tinyml}. In the microcontroller domain, Schizas et al.~\cite{schizas2022tinyml} deployed MLPs on ESP32 for industrial condition monitoring but logged timestamps over UART. Imteaj et al.~\cite{imteaj2023benchmarking} and Nguyen et al.~\cite{nguyen2024quantized} surveyed embedded AI execution frameworks over small sample sizes ($N<100$). Puranik et al.~\cite{puranik2024benchmarking} benchmarked vectorized networks on ESP32-S3 via ESP-NN. Ray~\cite{ray2022review} and Saha et al.~\cite{saha2022tinyml} surveyed TinyML paradigms, while Blalock et al.~\cite{blalock2020state} highlighted how software pruning benefits frequently fail to materialize on edge hardware. Knowledge distillation foundations were established by Hinton et al.~\cite{hinton2015distilling} and surveyed by Gou et al.~\cite{gou2021knowledge}.

Our work complements prior literature by providing an empirical on-device characterization of ultra-low-resource ($<4$\,KB) INT8 models on physical ESP32 silicon with high statistical density ($N=24,000$), zero-I/O timing, and arena memory accounting.

\section{Threats to Validity and Limitations}
We explicitly delineate the following scientific boundaries:
\begin{enumerate}
    \item \textbf{Single Silicon Target:} Evaluations were conducted exclusively on the dual-core Xtensa LX6 ESP32-D0WD-V3. Results do not directly generalize across other ISAs (ARM Cortex-M, RISC-V) or vector-extended variants (ESP32-S3).
    \item \textbf{Topology Scope:} Experiments focused on sub-4 KB fully-connected MLP architectures. Convolutional, recurrent, and transformer architectures exhibit different memory locality and tensor arena dynamics.
    \item \textbf{Software Stack Baseline:} Measurements evaluate portable reference C++ integer kernels in TFLM. Assembly-optimized vector libraries (ESP-NN) may achieve lower latencies.
    \item \textbf{Power and Energy Instrumentation:} We characterize latency and memory; power dissipation was not instrumented via hardware current shunts.
    \item \textbf{Empirical Latency vs. Formal WCET:} The maximum observed latency ($102\,\si{\micro\second}$) reflects empirical measurement distributions and does not constitute a formal static WCET bound.
    \item \textbf{Isolated Kernel Timing:} Timings isolate pure inference and exclude sensor ADC sampling, scaling, and communication bus latency.
\end{enumerate}

\section{Conclusion}
This paper presented an empirical on-device characterization and latency profiling of four serialized \texttt{FULL\_INT8} TinyML models deployed on physical ESP32-D0WD-V3 microcontroller silicon. Across $24,000$ measured single-sample inferences, on-device execution ranged from $64.55\,\si{\micro\second}$ to $89.90\,\si{\micro\second}$, demonstrating strict parameter-ordered monotonicity ($R^2 = 0.963$) and demonstrating that the evaluated \texttt{student\_a\_8\_4\_int8} model exhibited a $28.20\%$ lower isolated ESP32 inference latency than the uncompressed \texttt{mlp\_14f\_int8} baseline. We quantified an observed host-to-microcontroller latency slowdown between $62.87\times$ and $76.77\times$, unmasking host-side sub-microsecond noise-floor rank inversions. Furthermore, memory profiling verified that TensorFlow Lite Micro commits exactly $916\,\text{Bytes}$ of static tensor arena memory with zero dynamic heap allocations across $25,200$ executions. These verified findings provide defensible empirical baselines for edge intelligence in real-time cyber-physical and industrial diagnostic systems.
